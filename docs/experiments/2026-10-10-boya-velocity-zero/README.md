## 有效0次如何落实

原4次场景速度min/max为4/255，手部articulation请求4，刚体请求1。
本次场景min/max改为0/0，25个刚体（含手部各link和圆柱）及1个articulation请求全部0，
位置min/max16/255及各actor位置请求16保持。所有其他采集场景物理属性一致。
覆盖只写运行场景，在spawn后、PhysX初始化前执行，初始化后完整读回仍相同。

本地PhysxCfg规定最大actor请求夹到场景min/max；这与0请求、0/0上下限共同建立
有效0次的配置证据。原生tensor view没有暴露solver/iteration读取方法，
没有伪称直接测量内部kernel循环次数。[源码片段、路径、版本和hash](source_check.json)。
这是单独评估的引擎配置；没有修改已训练环境、源USD、安装包、任务、奖励公式或控制器。

结果支持“该迭代配置会影响本地速度/姿态一致性”，不能单凭一条闭环轨迹证明全部
求解机制或引擎bug。策略原来训练在4次环境，切换配置后接触轨迹也会变化，
不能由本次掉落判定0次训练后的能力。建议把0次视为后续短预算训练对照的候选，
进一步检验原Hora公式下能否同时获得保持和转动；本次授权的工作到诊断结束。

# 实物约束与下一阶段方案（讨论稿）

目标是在伯牙绳驱手的实际控制和感知条件下持续旋转圆柱，并用实验检验对物体尺寸、负载、接触条件和观测缺失的适应能力。本文件记录约束与候选方案，已有触觉承重转移控制原型，尚未接入真实驱动，也不代表已经解决实物迁移或形成论文创新。

## 已知条件与待确认事项

用户描述的手有五个手指，指腹可读三维力与阵列图像，可配合相机。当前实验使用 TH、FF、MF、RF 四指，腕部保持，LF 收起。首轮实物可采用固定手腕、人工置物和力闭环加载，记录撤去置物支撑后的操作；自动接近和抓取路径是另外的任务。

对 ROS 仓库 `28f4ba5649714c74c13f881891d579bfceb766e2` 的只读核对：

- `dexhand_bringup/config/dexhand_joint_controller.yaml` 配置 18 个主动关节及 `position`、`velocity`、`effort` 接口。
- `dexhand_control/hardwares/dexhand_hardware_interface/src/dexhand_hardware_interface.cpp` 将位置/速度接到 `angle_rad` / `speed_rad`，effort 直接接到驱动字段 `torque`。这些名字尚不能证明实物力矩单位、精度或力矩闭环性能。
- 同一写接口将接近零或绝对值大于 10 的速度值替换为 3.14。因此不能先验地把“写入零速度”当成该驱动的制停语义；需要确认控制模式与停止方式。
- 从动关节从主动命令列表中排除。还需确认各位置读数来自电机端、关节端还是软件估计，不能将仿真的所有关节角当作实物可测量量。

实际刷新频率、时延/抖动、力和阵列单位、零漂、坐标系、可用控制模式及停止语义仍需测量/确认。第一版按位置目标增量接口构思，使用力反馈形成外环，不预设已具备准确关节力矩控制。一次性的手和传感器标定是必要条件；泛化实验不为每个测试物体重新调权重或搜索专用动作库。

## 对算法有直接影响的约束

| 实际问题 | 控制器需要处理的量与行为 | 验证方式 |
|---|---|---|
| 绳弹性、回差、摩擦、关节耦合与标定误差 | 用实际驱动指令作为动作变量；保留近似运动学，以接触响应在线修正局部模型，记录模型置信度 | 先测小幅正反向命令的迟滞和接触响应，再做固定参数/在线修正的对照 |
| 摩擦和负载未知，表面变化 | 联合判断法向载荷、切向需求、接触迁移和滑移迹象；接近力限时减小转动需求 | 分别改变表面和质量，记录滑移、超力、掉落与转速；不只看转角 |
| 三维力偏置、坐标误差、阵列噪声 | 完成零点与方向校验、时间同步；用有置信度的接触特征 | 单独注入偏置、噪声、延迟及缺帧，再联合测试 |
| 相机遮挡或位姿跳变 | 相机可见时校正估计，短时遮挡由触觉/本体信息维持接触；置信度不足时降速或转入保持 | 使用可重复的遮挡时段，报告持续时间、估计误差与恢复行为 |
| 圆柱的旋转对称性 | 无纹理圆柱的轴向角度通常不能只靠外形观测；定义可观测任务量，独立测量评估真值 | 可先用可见标记或独立测量作转角真值；明确该信息是否输入控制器 |
| 求解慢、通信或视觉低频 | 接触控制与慢规划分开运行；计划附带时间戳和有效期，处理迟到计划与失联 | 记录每次计算耗时/截止时间，仿真中也不暂停物理等待优化 |
| 力限、行程与可达接触限制 | 判断任务是否可行，必要时保持或停止推进；不靠无限夹紧维持 | 测试接近行程/载荷边界的行为，并按实物能力设置限制 |

不能把静止时的切向力/法向力比直接当成已知摩擦系数；它只是当前摩擦需求的信息。未知摩擦、有限力和完全失去观测时不能保证任意物体继续转动，需要说明适用范围与退化行为。

阵列“图像”也要先确认类型：压力分布可提供接触质心、面积和变化，但不一定能恢复切向速度；含纹理或剪切信息的触觉图像有不同的可观测性。不能在没有数据验证时宣称已能从触觉准确得到物体转速或完整姿态。

## 候选算法结构

1. **接触与运动状态估计。** 融合三维力、阵列特征、可用的关节/电机反馈及间歇视觉，输出接触状态、滑移迹象、物体局部运动估计及各自置信度。仿真真值仅用于评估；控制器输入明确经过与硬件一致的传感通道。
2. **较快的接触控制。** 通过受限位置增量调整指腹载荷与切向推进，结合跟踪误差修正命令。实际频率由接口带宽和时延测试决定。夹紧力、关节增量及速度都有上限。
3. **较慢的动作规划。** 根据剩余手指的承重余量和观测可信度决定推进、卸载与重新接触的时机。以反馈触发接触切换，研究如何减少固定周期动作的回摆。换指要评估剩余接触提供的力和力矩，不能仅凭“还有两指”就认定能承重。
4. **不确定性下的执行。** 在近似模型上在线修正局部响应，并用模型/观测的不确定性影响动作幅度和换指选择。若新计划迟到或视觉/触觉异常，已有接触控制负责受限保持；不能沿用仿真暂停等待求解的执行方式。

这些是待比较的设计选项。是否需要采样 MPC、短时域优化或更简单的反馈形式，要由实测响应、观测能力和计算预算决定。“使用触觉”本身不构成创新；潜在研究问题是如何利用有误差和间歇观测下的接触状态与不确定性，可靠地决定承重转移和换指。

## 实验顺序与判据

- **先确认接口和观测。** 测量时间戳/频率、关节或电机响应、力坐标与阵列含义；用已知转动检查滑移/运动特征到底能测什么。记录实测范围后设置仿真扰动范围，不凭空声称某个范围符合实物。
- **原尺寸接触闭环。** 用 40×32 mm、50 g 建立保持和小幅转动，加入驱动误差、传感延迟与未知接触条件。保持成功与多圈成功分开计数。
- **同参数持续旋转。** 检验原尺寸及 1.25 倍尺寸、均为 50 g 的两圈目标，覆盖多个初始握持；再分开改变质量、摩擦、耦合/迟滞和遮挡。最终使用未参与选型调参的组合测试。
- **小范围实物验证。** 固定手腕、已建立的稳定握持，先验证保持/停止行为，再逐步验证换指与多圈操作。使用硬件标定的限制，不能直接照搬仿真的 12 N。
- **机制消融。** 比较固定周期、接触反馈触发、在线响应修正、置信度/不确定性处理，以及视觉持续可用/间歇可用。保持相同输入权限和评测协议，区分源码移植结果与新方法结果。

除净转角和成功率，还记录反向回摆、转速、载荷峰值、接触丢失持续时间、实际掉落、停止原因、遮挡恢复、求解与通信延迟。明确用户主动中断及未完成运行的统计处理。新评测协议若调整暂态容忍度，所有方法使用同一版本，同时保留当前严格协议的记录。

跨手泛化需要另一只真实或已验证模型的手才能支持结论。首阶段以伯牙手的闭环执行和物体/接触变化为范围，不把一个仿真物体的成功扩大成跨手或实物成功。

## P3 已实现的接口边界

新增 `research/closed_loop_control.py` 是只依赖 NumPy 的触觉控制原型。输入是带时间戳的四指三维力和已经发出的执行器位置请求；输出是下一周期的位置请求。没有读取仿真关节角、物体位姿、真接触法向或未知摩擦。固定/在线预测与普通反馈共用速度、行程和力限制，具体协议见 [P3](experiments/closed_loop_protocol.md)。

仿真有 10 ms 指令流水线；超过 10 ms 的求解结果丢弃，求解占用期间保持上一条指令。在线更新使用成熟触觉标签和实际请求历史，避免把重规划后未执行的候选动作学进去。输入缺帧/非有限会报告故障；真实停止仍需由硬件适配层根据驱动语义实现。没有写 ROS 仓库、没有发送真实手指令。

仍依赖初态名义 Jacobian，而不是已识别的电机—腱—关节映射。当前力数据来自理想接触求和；只测了执行延迟/增益/死区与 ±10° 坐标偏转代理。未覆盖力偏置、噪声、滑移可观测性、真实触觉采样延迟、未知摩擦、遮挡或不同接触拓扑。物理真值监视器能中止仿真，但它不是可部署的触觉安全层。

因此下一阶段硬件工作应先确认命令单位与停止语义、同步记录请求/实际可读的电机状态/触觉时间戳，再做同等幅度探测。需要的数据用于替换代理误差和名义动作方向；不能把这一轮计算开销达标等同于整套硬件链路可部署。

完整预声明窗口、固定/移动轴、奖励各项及原始文件hash见[数值证据](comparison.json)。

这些结果支持“本地接触状态下的速度信号会在真实旋转停滞或反向时仍提供正旋转奖励”。
偏差不是简单增加速度迭代就能修好；具体求解器内部机制仍未验证。
这不能证明Hora或Sharpa原奖励有缺陷，也不能单凭它判定灾难性遗忘。
16次日志还明确提示TGS超过4次速度迭代的行为近期变更，原文已存入证据；
本次未据此推断具体求解机制。

后续应先解决旋转速度输入与实际姿态变化的一致性，保留Hora公式作为参照，
再决定引擎修正或单独声明姿态差分输入变体并做短训练对照。
本次训练动作数为0，没有启动后续训练或第三个物理回合。
这是单策略、单初态的两配置诊断，不是多种子基线验证或硬件验证。

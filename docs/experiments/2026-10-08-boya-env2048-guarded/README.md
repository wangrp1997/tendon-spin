## 已实现的保护

- 训练使用独立 systemd 用户服务；启动闸门放行前，读取并确认实际限制：
  CPU 最多 4 核配额、任务 RAM 12 GiB 软限制/16 GiB 硬限制、禁止任务交换，
  nice +10 和低 I/O 优先级。监控位于服务外，保持正常优先级。
- 每秒监测显存、系统可用内存、内存等待、磁盘空间、GPU 利用率和训练心跳。
  显存 >10 GiB、系统可用内存 <12 GiB 等条件请求保存退出；紧急线为
  显存 >12 GiB 或系统可用内存 <8 GiB。
- 控制动作之间响应请求，保存可用检查点和诊断数据。8 秒无退出则发送
  SIGTERM，再等 5 秒强制回收整个专属服务；紧急情况直接回收。只操作本次
  任务，不结束桌面或其他任务。强制回收不保证最后的内存状态已保存。
- 本次服务有独立 300 秒运行上限；即使监控退出，systemd 仍会停止测试。
  无头、关闭相机。GPU 无 cgroup 显存硬上限；这些措施降低卡顿和资源耗尽
  风险，不能保证 GPU 驱动或内核故障时仍能响应。

保护验证先用了合成遥测和两个微型进程：10 个判断用例通过，实际验证正常
响应退出和忽略 SIGTERM 后强制回收两条路径，均已确认资源限制生效。
这些验证没有运行机器人或分配大块 GPU/RAM；与上述真实 2048 遥测分开记录。
本轮真实训练另外验证了协作保存退出路径。

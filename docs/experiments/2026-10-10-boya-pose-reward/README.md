# Boya旋转奖励改为姿态差分：已实现，未启动训练

2026-10-10，用户批准修改并要求记录/push。新训练入口默认
`--reward-profile hora_pose_delta`，原版可显式选择`hora_reported_velocity`。
[改动与验证协议](PROTOCOL.md)。这是Boya奖励输入适配，不是原始Hora基线。

现在从每个物理步的实际世界姿态四元数计算旋转向量，累计100步后除以0.05秒，
得到控制周期平均角速度，再传入原Hora奖励函数。采用float64计算后转回原生dtype。
原目标轴、奖励权重、裁剪及其他惩罚保持；PPO、网络、观测、动作和终止规则保持。
奖励目标发生改变，因而优势/价值目标和最终学习行为会改变。

训练与评估共用同一实现，奖励身份/源哈希写入结果和可恢复检查点；不同奖励不能
冒充同配置恢复。旧记录缺少奖励身份时按原输入解释。低层环境API维持原默认以兼容
旧调用者；新训练入口明确传递新配置。严格来源核对保留，历史权重/轨迹/成绩未修改。

仅对已有20M原4次配置30秒轨迹离线重算600个控制步，未新执行策略或仿真。

| 原轨迹窗口 | 旧旋转奖励均值 | 姿态差分旋转奖励均值 |
| --- | ---: | ---: |
| 0–5秒 | +0.238682 | +0.067873 |
| 5–20秒 | +0.347928 | +0.005198 |
| 20–30秒 | +0.367686 | −0.004294 |

20–30秒实际沿原目标轴平均−0.004294rad/s；新奖励对应这段轻微反转，
不再由报告速度给出+0.367686的旋转分。该段总奖励均值从+0.233122变为−0.138857，
其他奖励项直接保留。新角速度与独立SciPy结果最大差2.84e-8rad/s；
原旋转奖励重现最大差5.97e-8，均通过协议阈值。

3项旋转输入CPU测试和1项既有完整学习器恢复测试通过，恢复测试同时拒绝奖励配置
不匹配；9个修改的Python文件语法核对通过。静止姿态最初严格相等断言观察到约
1.90e-19rad/s浮点残差，改为1e-12容差后通过，没有添加奖励死区或物理阈值。
[离线重算结果与原始来源哈希](verification_result.json)、[代码身份和验证摘要](implementation.json)。

奖励仍沿固定原目标轴投影，主评估仍按移动圆柱轴积分；倾斜时二者定义不同。
裁剪也使平均奖励不等于净角速度。这次确认的是奖励输入行为，尚未验证新策略能保持
或持续旋转。旧20M主成绩和停止原因保持原记录，离线重算不替代任何独立执行成绩。
